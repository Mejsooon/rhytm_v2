# Strony 2.0, krok 3: Hasła jako moduł i onboarding — plan wdrożenia

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hasła są stałym modułem `/hasla` z tą samą tabelą co strony (edycja w komórkach, Notatka, Kategoria). Typ „secret” działa tylko na stronie systemowej. Onboarding nie ma kafelków celów ani Haseł i Subscriptions w stronach.

**Architecture:**
- **Baza.** Strona haseł zostaje zwykłą stroną z nową flagą `pages.is_system`. Wyzwalacze w bazie pilnują stałych kolumn i zakazu „secret” poza nią. Stronę systemową tworzy funkcja `ensure_passwords_page()` (SECURITY DEFINER), a migracja adoptuje istniejącą stronę „Passwords” funkcją `adopt_passwords_page(uuid)`.
- **Interfejs.** `PageTable` dostaje tryb modułu: stałe kolumny, tylko do odczytu przy zamkniętym sejfie i komórki secret szyfrowane w przeglądarce. `TemplatePageView`, `RowEdit` i `RowPreview` znikają.
- **Onboarding.** Krok 3 i krok 5 według makiet S2Onboarding*, a podgląd dostaje blok „Ten tydzień”.

**Tech Stack:** Next.js 16 (cacheComponents), React 19, Supabase (Postgres, pgTAP w CI), WebCrypto (istniejący `src/features/vault`), Tailwind 4, Vitest, Playwright (tylko CI).

**Spec:** `docs/superpowers/specs/2026-11-22-strony-2-design.md`. Plan obejmuje punkty 4, 6 (część o hasłach), 12 i 14 oraz „Decyzje Claude” (przechowywanie haseł, typ secret, Kategoria jawna, onboarding).

## Rulings (decyzje Claude do sprawdzenia przez Mejsona)

- **Flaga `pages.is_system`** zamiast `template_key = 'passwords'`. Jest jednoznaczna i pozwala filtrować listy. `template_key` strony systemowej zostaje `'passwords'`.
- **Wyjątek dla funkcji systemowych** przez lokalną zmienną transakcji `rhytm.system_write = 'on'` ustawianą tylko w funkcjach SECURITY DEFINER (`ensure_passwords_page`, `adopt_passwords_page`). Klient przez PostgREST nie ustawi jej sam.
- **Zakaz zmiany nazw kolumn modułu.** Spec mówi o dodawaniu, usuwaniu i typie, ale stałość nazw upraszcza migrację i rozpoznawanie kolumn.
- **Strona systemowa jest nieusuwalna,** nie zmienia się jej tytułu ani ikony, nie da się jej zduplikować ani przenieść między stronami. Wejście na `/strony/<id strony systemowej>` przekierowuje na `/hasla`.
- **Szyfrowanie sekretu przy zapisie komórki:** przy Enter albo wyjściu z komórki, bez opóźnienia 600 ms. Każdy szyfrogram ma nowe IV, a tekst jawny trzymamy jak najkrócej.
- **Telefon:** arkusz wiersza pokazuje sekret maską z oczkiem i kopiowaniem, a edycja sekretu w arkuszu idzie tym samym polem co na webie (szyfrowanie przy zapisie arkusza). Dopracowanie wyglądu należy do Etapu 3.
- **Ten tydzień w podglądzie onboardingu:** kafelki z celów z kroku 3, z zerowymi wartościami („0 / N”, „0,0 / N km”, „— / X h”).

**Interfaces (Produces):**
- Kolumna `public.pages.is_system boolean not null default false` i unikalny indeks częściowy `pages_one_system_per_user ON pages(user_id) WHERE is_system`.
- `public.ensure_passwords_page() returns uuid`:
  - SECURITY DEFINER, `search_path = ''`;
  - zwraca id strony systemowej `auth.uid()`, a jeśli jej nie ma, tworzy ją: tytuł „Hasła”, ikona `lucide:lock`, `template_key 'passwords'`, jeden blok tabeli `content = {name:'', settings:{sort:[],filters:[],hidden_field_ids:[],column_summaries:{},pinned_cards:[],column_widths:{}}}`, kolumny według Global Constraints;
  - jest idempotentna przy dwóch równoległych wywołaniach (`ON CONFLICT` na indeksie albo `pg_advisory_xact_lock`);
  - `grant execute` dla `authenticated`.
- `public.adopt_passwords_page(p_user uuid) returns uuid`:
  - SECURITY DEFINER;
  - dla użytkownika z dokładnie jedną nieusuniętą stroną `template_key='passwords'` sprawdza układ kolumn: tytuł text = Serwis, jedno pole secret = Hasło, jedno url = URL, pozostały jeden text = Login, razem 4 pola w jednym bloku tabeli;
  - ustawia `is_system`, dopisuje Kategorię (select, `config {options:[]}`) i Notatkę (secret) na końcu, nadaje stałe nazwy i kolejność;
  - przy kilku stronach albo innym układzie robi `raise exception` z czytelnym komunikatem po polsku;
  - bez strony zwraca null;
  - wiersze i zaszyfrowane wartości zostają nietknięte;
  - `revoke execute` od `public` i `authenticated`, wołana tylko przez migrację i testy.
- **Migracja:**
  - najpierw `raise exception`, jeśli istnieje pole secret na stronie innej niż `template_key='passwords'` (także w koszu);
  - potem pętla `adopt_passwords_page` po użytkownikach.
- **Wyzwalacze** (z wyjątkiem, gdy `current_setting('rhytm.system_write', true) = 'on'`):
  - `page_fields` BEFORE INSERT: typ `secret` tylko gdy strona bloku jest `is_system`, a wstawienie pola do strony systemowej jest zabronione;
  - `page_fields` BEFORE UPDATE: na stronie systemowej wolno zmienić tylko `config`, a nie `name`, `type`, `position` ani `is_title`; poza nią zmiana typu na `secret` jest zabroniona (zastępuje dzisiejszy `page_fields_secret_type_guard`);
  - `page_fields` BEFORE DELETE: zakaz na stronie systemowej;
  - `pages` BEFORE UPDATE: `is_system` niezmienne, a na stronie systemowej `title`, `icon` i `deleted_at` niezmienne;
  - `pages` BEFORE DELETE: zakaz dla systemowej;
  - `page_blocks` BEFORE INSERT/UPDATE OF deleted_at/DELETE: zakaz na stronie systemowej.
- `duplicate_page`, `move_page` i `reorder_pages` odmawiają dla strony systemowej. Zmień je w migracji albo zostaw wyzwalaczom, jeśli dają czytelny błąd.
