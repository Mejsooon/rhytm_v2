# 2026-11-16 — Etap 0: fundament

## Co zrobione
- Spec całej aplikacji (`docs/superpowers/specs/2026-11-16-rhytm-design.md`), mapa etapów, makiety web i telefon, plan Etapu 0.
- Szkielet Next.js 16 z Vitest, Playwright i CI (GitHub Actions).
- Tokeny rhytm, font Geist, shadcn (Radix), logo, kontrolki: przyciski, pola, dymki, okna i arkusze, listy, segmenty, przełączniki, checkboxy, chipy, plakietki, wybór daty i godziny.
- Supabase: tabela `profiles` z RLS, klienci SSR, proxy z sesją i przekierowaniami.
- Konto: logowanie (z Google i Turnstile), rejestracja (reguły hasła, sprawdzanie wycieków HIBP), potwierdzenie e-maila, reset hasła, link wygasł.
- Powłoka: sidebar, dymek konta, dolny pasek na telefonie, puste moduły, 404, manifest PWA.
- e2e konta i powłoki, zrzuty 1440 i 390 px względem makiet, instrukcja wdrożenia.

## Decyzje
- Etapy wdrażane po kolei według mapy etapów. Każdy ma osobną gałąź, a scalenie następuje po akceptacji Mejsona.
- Migracje uruchamia Mejson: `pnpm exec supabase db push --remote` (nowsze CLI domyślnie celuje w lokalną bazę).
- Znacznik resetu hasła to ciasteczko podpisane HMAC (userId i czas wygaśnięcia), bo `verifyOtp` nie daje `amr`.
- `SUPABASE_SECRET_KEY` nie trafia do Vercela.

## Otwarte wątki

## Błędy
- Reset hasła nie rozpoznawał sesji „recovery”. Rozwiązanie: podpisane ciasteczko zamiast `amr` i nagłówki no-cache w proxy.
- Limity czasu HIBP i Turnstile dawały niewidoczne błędy. Teraz komunikaty są widoczne i są limity czasu.
